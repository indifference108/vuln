# 弱密钥「公示初始密码规则」登录验证作业单（2026-11-10）

> 本作业单只记录**只读勘察结论**与**可执行工具**，不包含任何真实学号 / 证件号 / 口令。
> 红线（README 工作规范 / notes §9 / §7.14 川大模式）：不使用未授权系统的真实数据；只判「登录成功 + 身份页」，不翻阅数据；单入口 ≤5 组、限速 1.5s；验证码用户人工破；全程录屏。

## 一、为什么这一步由你本人执行

1. **项目分工**：历史 4 个已收录的弱口令案例（川大 CNVD-2026-39400、福建农林 39401、中国农大、河南农大）都是「公示明文学号 + 公示初始密码规则 → 用户本人录屏登录 → 报送」定案的，登录与录屏一直是用户环节（notes §7 待办第 1 条、§9）。
2. **材料缺口**：本轮只读勘察只统计了公示页是否存在成串学号 / 附件，**没有落地任何真实号码**；没有公示材料就无法构造凭据。
3. **合规红线**：README 明确「不使用未授权系统的真实数据；生产环境只做指向自建金丝雀的只读验证」。用真实在校生的学号 / 证件号登录生产账号属于访问真实用户数据，超出只读边界。
4. **送审证据**：CNVD 报送包六件套里必须有录屏 mp4（§6 标准），录屏只能由你本人操作产生。

## 三、已交付的可执行工具（本地自检跑通）

| 文件 | 作用 |
|---|---|
| `scan_sync/_weakpwd_login_template.py` | 脱敏验证模板：单入口 ≤5 组、限速 1.5s、只判登录成功/身份页、不翻阅数据、不落地真实号码、**遇验证码立即停机**、生产目标必须显式 `--i-have-authorization` |

## 四、你只需三步

1. 准备公示材料（带明文学号 / 证件号后六位的公开名单），存成 CSV：`sid,credential`（**别发给我，放本地即可**）。
2. 浏览器打开目标登录页，人工破验证码；执行：
   ```
   C:\Python312\python.exe E:\kimi\scan\_weakpwd_login_template.py ^
     --target https://{{TARGET}} --path {{LOGIN_PATH}} ^
     --ufield {{USER_FIELD}} --pfield {{PASS_FIELD}} ^
     --credentials <你的CSV> --i-have-authorization
   ```
   同时录屏（CNVD 报送必需）。字段与上表按目标填；CAS / ASP.NET 站点需补 `__VIEWSTATE`、`lt`、`execution` 等隐藏字段，模板支持扩展。
3. 把录屏 mp4 和脚本输出丢回对应漏洞目录，我按 §6 六件套标准出《漏洞复现过程.docx》+ 报送 zip + README 索引，并 push 到 `vuln-repo`。
